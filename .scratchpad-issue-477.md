# Issue #477: Case-Insensitive Matching Without Index Support

## Summary
Resolved performance issue where `func.lower()` calls on both sides of joins prevented database index usage, causing table scans that degrade performance as data grows.

## Solution Implemented
Added normalized lowercase columns with indexes to enable efficient case-insensitive matching:

### Database Schema Changes (Migration: dae9onwpk4jh)
1. **recipe_ingredients.ingredient_name_lower** - indexed normalized column
2. **inventory_items.name_lower** - indexed normalized column
3. **stores.name_lower** - unique indexed normalized column

### Model Changes
- Added SQLAlchemy event listeners to automatically maintain normalized columns on insert/update
- Models: `RecipeIngredient`, `InventoryItem`, `Store`

### Query Updates
1. **feed_service.py** (lines 66, 85):
   - Changed: `func.lower(RecipeIngredient.ingredient_name) == func.lower(InventoryItem.name)`
   - To: `RecipeIngredient.ingredient_name_lower == InventoryItem.name_lower`
   - Enables index usage for ingredient matching in make-now feed queries

2. **task_worker.py** (line 124):
   - Changed: `func.lower(Store.name) == func.lower(store_name)`
   - To: `Store.name_lower == store_name.lower()`
   - Enables unique index usage for store lookups

### Testing
- Added test: `test_make_now_case_insensitive_ingredient_matching` in test_feed.py
- Updated test: `test_process_receipt_task_case_insensitive_store_lookup` in test_task_worker.py
- Verified backward compatibility maintained

## Performance Impact
- **Before**: Table scans on every join (O(n*m) for n recipes × m inventory items)
- **After**: Index lookups (O(log n) with B-tree indexes)
- **Trade-off**: ~2x storage for affected columns, automatically maintained
